## 待处理问题

### AUD-A11Y-001 — 图片灯箱缺少可访问名称，焦点管理不完整

- 类别：可访问性 / 客户端交互
- 严重度：**Medium**；置信度：99；状态：open；处置：Fix
- 位置：`src/lib/lightbox.ts:47` 创建图片链接，`:55` 初始化灯箱，`:59` 和 `:62` 为打开/关闭回调。

**证据与复现**：在 `/article/2026/05/monthly-summary/` 聚焦第一张正文截图链接，按 Enter 打开，Tab 到关闭控件，再按 Esc。
实际 Chromium 生产预览中，自动创建的链接只有空 `alt` 图片，没有文本或 `aria-label`；灯箱的 `role="dialog"` 没有 `aria-label` / `aria-labelledby`。
打开时焦点仍留在背景图片链接，关闭后 `document.activeElement.tagName` 为 `BODY`，没有恢复到触发链接。当前 13 张正文截图使用空 alt，使该入口名称问题有实际覆盖面。

**影响**：读屏用户难以识别截图入口和弹窗用途；键盘用户关闭图片后丢失阅读焦点。
现有灯箱测试验证开关、Esc 和换页清理，未验证名称及焦点，因此全套测试通过仍会遗漏此问题。

**建议**：为内容截图补充描述；自动包装链接时提供“查看大图：…”名称，并向灯箱传递图片描述。
为弹窗命名，打开后聚焦内部控件；普通关闭后恢复触发链接焦点，换页销毁时避免恢复已脱离文档的节点。
依据为 [WAI-ARIA 模态对话框模式](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)。

**建议验证状态**：Strongly Supported；已验证问题和集成位置，未实施或验证修复补丁。
建议增加一条覆盖“入口名称 → 打开后焦点 → Esc 后恢复 → 换页不聚焦旧节点”的浏览器回归。

### AUD-LIC-001 — 分发字体子集时没有随附 OFL 许可证

- 类别：第三方资产 / 许可证随附
- 严重度：**Low**；置信度：98；状态：open；处置：Fix
- 位置：`src/assets/fonts/`，`scripts/subset-font.mjs:47`，`src/integrations/serif-subset.mjs:50`。

**证据**：仓库包含 Noto Sans SC 和 Noto Serif SC 两个字体子集，构建还会向 `dist/fonts/` 发布 WOFF2。
字体 name 表保留 ID 0–6，其中有原版权信息，但没有许可证字段；仓库和 `public/` 没有字体 OFL 文本。
根目录 `LICENSE` 为项目作者的 MIT 许可证。

**影响**：第三方字体分发缺少随附许可材料。上游 [Sans 许可证](https://raw.githubusercontent.com/notofonts/noto-cjk/main/Sans/LICENSE) 和 [Serif 许可证](https://raw.githubusercontent.com/notofonts/noto-cjk/main/Serif/LICENSE) 的 OFL 1.1 条款 2 要求分发副本包含版权声明和许可，可通过独立文本或可读元数据提供。
此处仅确认随附材料缺失，不作进一步法律结论。

**建议**：保留两款字体对应版权声明和 OFL 全文，并放入随站点复制的 `public/fonts/` 目录；在项目许可说明中明确第三方字体的许可归属。

**建议验证状态**：Strongly Supported；已核对上游许可及本地产物组织，未实施。
建议构建验收同时检查字体和随附许可文件存在。

### AUD-DEP-001 — 开发工具链锁定了受公告影响的 undici

- 类别：依赖 / 开发工具可靠性
- 严重度：**Low**（按本站部署模型）；置信度：100；状态：open；处置：Fix
- 位置：`package-lock.json:8715`（Wrangler），`:6470`（Miniflare 依赖），`:6479`（嵌套 undici）。

**证据**：锁定链为 Wrangler `4.152.0` → Miniflare `5.20261019.2-beta` → undici `7.29.1`。
[上游原始公告 GHSA-xjj6-f33q-929c](https://github.com/nodejs/undici/security/advisories/GHSA-xjj6-f33q-929c) 覆盖该版本：恶意远端响应可使使用相关 `fetch()` 的 Node 进程退出；7.x 修复版为 `7.30.1`。

**影响**：开发/预览工具链保留已知的可用性风险。当前站点发布纯静态资源，未发现访客可触达这条 Node 调用链；不能把上游 High 等同于本站线上 High。

**建议**：通过正常依赖更新升级 Wrangler 和锁文件。已核对 npm registry 存在 Wrangler `4.153.0` → Miniflare `5.20261023.0-beta` → undici `7.30.1` 的修复路径。

**建议验证状态**：Strongly Supported；已核对版本依赖关系，未安装候选版本或验证更新后的构建。
更新后运行现有检查及 Workers 本地预览。建议持续扫描依赖，并区分线上运行依赖、开发依赖和不可达调用。

### AUD-SEO-001 — 《猫》的页面与分享描述为空

- 类别：内容元数据 / SEO
- 严重度：**Low**；置信度：100；状态：open；处置：Fix
- 位置：`src/layouts/Post.astro:32`，`src/content/blog/2026-09-26_Cat.md:12`。

**证据**：文章未填 `description`，正文第一行即 `<!-- more -->`。`excerpt()` 按约定只取该标记前的文本，返回空串；`??` 不会回退空串。
实际 `dist/article/2026/09/cat/index.html` 的 description、`og:description` 和 JSON-LD description 均为空。

**影响**：该文章缺少站方提供的搜索及分享摘要，展示依赖抓取方自行提取。

**建议**：给该文章补充显式 `description`，或者为文章 SEO 单独增加空值回退。
首页不显示该文章摘要符合现有 `more` 语义，应保留，避免全局修改 `excerpt()` 导致列表行为变化。

**建议验证状态**：Strongly Supported；已核对源码、调用链和 HTML，未实施。
建议对公开文章的最终 SEO description 增加非空验收，允许列表摘要为空。
